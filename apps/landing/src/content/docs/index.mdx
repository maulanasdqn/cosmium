## The problem Cosmium solves

Generic stealth tooling patches the automation API — `navigator.webdriver`, CDP
tells, the headless UA prefix. That closes one class of detection and leaves
another wide open: the **hardware-absence tells** that give away a container.

A headless Chromium in Docker reports SwiftShader as its WebGL renderer, an
empty `enumerateDevices()`, Linux Client Hints under a Windows user agent,
Docker bridge IPs in WebRTC candidates, UTC as its timezone, and an 800×600
screen. No amount of JavaScript injection fixes those convincingly, because the
page can ask the same question through a Worker, an iframe, or a property
descriptor check and catch the lie.

Cosmium fixes them **in the C++**, before any JavaScript runs.

## Thirty seconds in

```bash
cargo install cosmium-cli

# Check that a fingerprint profile is internally coherent
cosmium profile validate win11_rtx3060_en-us

# Scrape a page through the patched browser
cosmium scrape page \
  --profile profiles/win11_rtx3060_en-us.json \
  --extract "title=h1" \
  --screenshot \
  https://example.com
```

The `scrape` and `run` subcommands need a built Chromium binary. `profile`
validation, listing, and LLM authoring work without one.
